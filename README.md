# 실기 서술형 문제 출제·채점 앱

자격증 실기(서술형) 시험 대비용 랜덤 출제 및 AI 채점 웹앱입니다.
자격증이 바뀌어도 **코드 수정 없이 자격증 팩(문제 데이터)만 교체**하면 그대로 쓸 수 있습니다.

- 1인 개인용 (로그인·계정 없음)
- 화면형 웹 UI (모바일 브라우저 대응)
- 데이터는 SQLite 파일 하나에 영구 저장

**Node.js 22.5 이상**이 필요합니다 (DB로 내장 `node:sqlite` 를 씁니다).

## 실행 (윈도우)

프로젝트 폴더의 **`앱실행.vbs`** 를 더블클릭하면 끝입니다.
터미널 창 없이 서버가 뜨고, 주소창·탭이 없는 독립 창으로 화면이 열립니다.

바탕화면에 두려면 `앱실행.vbs` 오른쪽 클릭 → 보내기 → **바탕 화면에 바로 가기 만들기**.
파일 자체를 옮기면 앱 폴더를 못 찾습니다. 반드시 '바로 가기'로 만드세요.

- 처음 한 번은 부품 설치와 화면 빌드 때문에 몇 분 걸리고, 진행 상황이 보이도록 검은 창이 뜹니다.
  그 뒤로는 창 없이 몇 초 만에 뜹니다.
- 업데이트로 `package.json` 이나 화면 소스가 바뀌면 알아서 다시 설치·빌드합니다.
- 이미 켜져 있으면 창만 새로 엽니다.
- 시작하지 못하면 오류 내용을 메시지 상자로 보여줍니다. 자세한 기록은 `server/data/launch.log`.

앱 창은 Edge 또는 Chrome 의 앱 모드를 씁니다. 둘 다 없으면 기본 브라우저로 열립니다.

**끄려면** 화면 오른쪽 위의 **종료** 버튼을 누르세요. 창만 닫으면 서버가 남아 있습니다.
창을 이미 닫아버렸다면 같은 폴더의 **`앱종료.vbs`** 를 더블클릭하면 됩니다.
(이 폴더에서 실행 중인 서버만 골라서 끝내므로 다른 Node 프로그램은 건드리지 않습니다.)

폴더 이름을 바꾸거나 업데이트를 덮어쓰기 전에는 반드시 먼저 종료하세요.
서버가 폴더를 잡고 있으면 "다른 프로세스에서 사용되고 있습니다" 오류가 납니다.

폴더 이름은 원하는 대로 바꿔도 됩니다. 두 `.vbs` 는 자기 위치를 기준으로 동작합니다.

## 실행 (터미널 / macOS / Linux)

```bash
npm start
```

준비가 안 돼 있으면 알아서 설치·빌드한 뒤 서버를 띄우고 창을 엽니다.
창이 안 열리면 직접 http://localhost:4000 으로 접속하세요. 끌 때는 `Ctrl+C`.

데이터는 `server/data/app.db` 파일 하나에 쌓입니다. 이 파일만 백업하면 문제은행과 오답노트가 보존됩니다.

### 휴대폰·태블릿에서 쓰기

**같은 와이파이**에 연결되어 있으면 됩니다. PC에서 앱을 켜둔 채로,
**문제 관리** 화면에 표시되는 `http://192.168.x.x:4000` 주소를 휴대폰 브라우저에 입력하세요.
화면은 모바일에 맞춰 동작합니다.

- PC가 켜져 있고 앱이 실행 중일 때만 됩니다.
- 처음 접속할 때 윈도우 방화벽이 물으면 **개인 네트워크**에 허용해 주세요.
- **로그인 기능이 없습니다.** 같은 네트워크에 있는 누구나 접속할 수 있으니
  공용 와이파이에서는 쓰지 마시고, 인터넷에 직접 열지 마세요.

### 코드를 고치면서 쓸 때

```bash
npm run dev     # 서버(4000) + 프론트(5173), 저장하면 바로 반영
```

브라우저에서 http://localhost:5173 접속.

## 채점 방식 두 가지

앱은 **키 없이 그대로 쓸 수 있습니다.** 기본값은 키워드 대조 채점입니다.

| | 키워드 대조 (기본) | AI 의미 기반 |
|---|---|---|
| 설정 | 없음 | `.env` 에 `ANTHROPIC_API_KEY` |
| 인터넷 | **불필요** | 채점할 때마다 필요 |
| 비용 | 없음 | API 사용료 |
| 판정 | 등록한 키워드가 답안에 있는지 | 같은 뜻을 다르게 써도 인정 |

현재 어느 방식으로 돌고 있는지는 **문제 관리** 화면 위쪽에 표시됩니다.

### 오프라인 동작

`npm run setup` (최초 1회 부품 설치)에만 인터넷이 필요하고, 그 뒤로는 완전히 오프라인으로 동작합니다.
서버·DB·화면이 모두 PC 안에 있고, 외부로 나가는 통신은 Claude API 호출 하나뿐입니다.
API 키를 설정하지 않으면 그 호출 자체가 일어나지 않습니다.

### AI 채점을 쓰고 싶다면

```bash
cp .env.example .env
```

`.env` 를 열어 `ANTHROPIC_API_KEY` 를 채우고 앱을 다시 시작하세요.

### 키워드 대조 채점의 한계

등록한 키워드가 답안에 글자 그대로 있는지만 봅니다. 같은 뜻을 다른 말로 쓰면
(`투입` ↔ `주입`, `NH3` ↔ `암모니아`) 인정되지 않을 수 있습니다.
엑셀 항목을 적을 때 답안에 쓸 법한 표현으로 적어두면 오판정이 줄어듭니다.

### 환경 변수

| 변수 | 설명 |
|---|---|
| `ANTHROPIC_API_KEY` | 키워드 추출·의미 기반 채점용 Claude API 키. **없으면 로컬 규칙 채점으로 자동 폴백**합니다(정확도 낮음). |
| `CLAUDE_MODEL` | 사용할 모델. 기본 `claude-sonnet-5` |
| `PORT` | 서버 포트. 기본 `4000` |
| `EXTRACT_CONCURRENCY` | 문서 파싱·키워드 추출 시 Claude 동시 호출 수. 기본 `4`. 429가 뜨면 낮추세요. |
| `DB_PATH` | SQLite 파일 경로. 기본 `server/data/app.db` |
| `TZ` | 오답노트 기간 필터 기준 시간대. 예 `Asia/Seoul` |
| `OPEN_BROWSER` | `0` 으로 두면 `npm start` 가 브라우저를 열지 않습니다. |

프로젝트 루트의 `.env` 는 서버가 시작할 때 자동으로 읽습니다. 셸에 이미 설정된 값이 있으면 그쪽이 우선합니다.

## 사용 흐름

1. **문제 관리**에서 자격증 팩을 만듭니다 (예: 수질환경기사).
2. 문제를 등록합니다. **엑셀 양식**(권장) 또는 기출 문서(**docx · pdf · txt**)를 업로드하면
   미리보기가 뜹니다. 워드·PDF는 문서 구조에 따라 문제 경계를 잘못 잡을 수 있으니
   양이 많거나 정확도가 중요하면 엑셀 양식을 쓰세요.
3. 훑어보며 문제 본문·참고자료·요구 항목 수(N)를 고치고 **확인하고 저장**을 누르면,
   그 시점에 요구 항목 수와 키워드 그룹이 자동 추출되어 문제은행에 반영됩니다.
   한 번에 **최대 500문제**까지 등록할 수 있고, 진행률이 표시됩니다.
4. **홈 → 문제 풀기 → 1/5/10문제** 선택 후 답안을 모두 작성하고 한 번에 제출합니다.
   문제은행 전체에서 그 개수만큼 랜덤으로 뽑습니다.
5. **채점 결과**에서 문제별 점수와 인정/부족 항목을 확인합니다.
6. **오답노트**에서 누적 오답이 많은 문제부터 복습합니다.

자격증을 바꿀 때는 새 팩을 만들어 문서를 올리고, 팩을 **활성화**만 하면 됩니다.

### 엑셀 양식으로 등록하기 (권장)

문제 관리 화면의 **엑셀 양식 내려받기** 버튼, 또는 저장소의
[`data/templates/문제등록_양식.xlsx`](data/templates/문제등록_양식.xlsx)를 받아 채운 뒤 업로드하면 됩니다.

| 열 | 필수 | 설명 |
|---|---|---|
| 번호 | | 본인 정리용. 앱은 순서만 사용합니다. |
| 문제 | **필수** | 문제 발문 |
| 모범답안 | **필수** | 채점 근거가 되는 정답/해설 전문 |
| 요구항목수 | | "3가지 서술"의 3. 비우면 문제 본문에서 자동 인식 |
| 항목1~8 | | 정답으로 인정할 항목을 하나씩 나눠 기재. 앞에 `*`를 붙이면 필수 항목 |

**여러 항목을 적을 때는 항목 열에 하나씩 나눠 넣는 것이 가장 정확합니다.** 모범답안 칸에 몰아서 적는다면
셀 안에서 `Alt+Enter`로 줄을 바꾸세요. 줄바꿈 외에 `1. 2. 3.`, `①②③`, `- ` 불릿, 문장 종결(`…다.`)도
항목 경계로 인식합니다. 쉼표(`,`)와 슬래시(`/`)는 `질소, 인 등 영양염류`나 `F/M비`처럼 항목 내용 안에
자주 들어가므로 구분자로 쓰지 마세요.

**항목 열을 채우면** 그 내용이 그대로 채점 기준이 되어 AI 추출을 거치지 않습니다.
등록이 즉시 끝나고 API 비용도 들지 않으며, 채점 기준을 직접 통제할 수 있습니다.
정답 후보를 요구항목수보다 많이 적어도 됩니다 (3가지 문제에 항목 5개 → 그중 3개만 맞히면 만점).
항목 열은 **8개**까지 있어서, 정의와 대책이 섞이거나 조건이 둘로 나뉘는 문제도 한 행에 담을 수 있습니다.
비워두면 모범답안을 읽고 AI가 항목을 나눠줍니다.

#### 필수 항목 (`*`) — 복합 문제용

`부영양화의 정의를 쓰고 방지대책을 3가지 서술하시오.`처럼 성격이 다른 요구가 섞인 문제는
항목 앞에 `*`를 붙여 **반드시 답해야 하는 항목**으로 지정합니다.

| 열 | 값 |
|---|---|
| 요구항목수 | 4 (정의 1 + 대책 3) |
| 항목1 | `*정의: 영양염류 유입으로 조류가 과다 번식해 수질이 악화되는 현상` |
| 항목2~8 | 대책 후보 (요구항목수보다 많아도 됨) |

필수 항목은 맞힌 만큼 그대로 인정되고, 나머지 항목은 `요구항목수 - 필수 개수`개까지만 인정됩니다.
정의를 빼먹고 대책만 4개 써도 3/4 = 4점(부분정답)에 그치고, 채점 결과에 필수 항목 누락이 표시됩니다.

**복합 문제는 요구항목수를 직접 적어주세요.** 비우면 문제 본문의 "3가지"가 잡혀 정의 몫이 빠집니다.
필수 항목 수가 요구항목수보다 많으면 요구항목수를 필수 개수로 올려 채점합니다.

조건이 둘로 나뉘는 문제(예: 비저항이 낮을 때와 높을 때)는 항목 8칸에 양쪽을 모두 넣고
각 조건의 발생현상을 `*` 로 필수 지정하면 됩니다. 이때 **항목 이름이 서로 겹치지 않게** 적으세요.
양쪽에 똑같이 `습도 조절` 이라고만 적으면 답안에 한 번만 써도 두 항목 모두 인정됩니다
(`가스 증습으로 습도 조절`, `탈진 주기 단축` 처럼 구분되게 적으면 됩니다).

양식 파일을 다시 만들려면:

```bash
npm run template
```

문서 없이 CLI로 한 번에 적재하려면:

```bash
node server/scripts/seed.js data/samples/수질환경기사_실기_샘플.txt 수질환경기사
```

## 채점 규칙

모든 문제는 **5점 만점**, 백분율 기반 부분점수, **0.5점 단위 반올림**입니다.

| 문제 유형 | 점수 |
|---|---|
| 요구 항목 수 N이 있는 문제 (`3가지 서술하시오`) | `min(맞춘 그룹 수, N) / N × 5` — N을 넘겨 써도 가점·감점 없음 |
| 필수 항목(`*`)이 섞인 문제 | `(맞춘 필수 + min(맞춘 선택, N − 필수 수)) / N × 5` |
| N이 없는 일반 서술형 | `매칭된 키워드 수 / 전체 키워드 수 × 5` |

매칭은 **단순 문자열 포함이 아니라 의미 기반**입니다. 같은 뜻을 다른 표현으로 썼으면 인정합니다.

| 매칭 비율 | 판정 |
|---|---|
| 100% | **O** 정답 |
| 50% 이상 100% 미만 | **△** 부분정답 |
| 50% 미만 | **X** 오답 |

오답노트에는 **X와 △를 모두 누적**하며, △는 부분오답으로 구분 표시합니다.

### 출제 대상에서 제외되는 문제

참고자료가 비어 있으면 채점 기준(키워드)을 만들 수 없습니다. 이런 문제는 **저장은 되지만 랜덤 출제에서
자동으로 제외**되며, 문제 관리 화면에 `채점 기준 없음 · 출제 제외`로 표시됩니다.

문제 본문만 보고 키워드를 지어내지는 않습니다. 그렇게 하면 답안을 "문제에 쓰인 단어"와 대조하게 되어
채점이 무의미해지기 때문입니다. 문제 관리에서 참고자료를 채워 다시 등록하거나, `채점 기준 없음` 필터에서
일괄 삭제할 수 있습니다.

## 알려진 제약

- 구형 `.doc`는 지원하지 않습니다. `.docx`로 저장 후 업로드하세요.
- 워드·PDF 자동 분리는 문서 구조에 의존합니다. 번호 매김이 불규칙하면 여러 문제가 하나로 합쳐질 수
  있으니, 미리보기에서 확인하거나 엑셀 양식을 사용하세요.
- `ANTHROPIC_API_KEY`가 없으면 키워드 추출과 채점이 로컬 규칙(문자열 포함 여부)으로 동작합니다.
  동작 확인용이며 실제 학습에는 API 키 설정을 권장합니다.
- 그룹 매칭 시 **부분 일치**(항목은 맞지만 설명이 불완전한 경우) 처리 방식은 아직 확정되지 않았습니다.
  현재는 그룹 단위로 인정/불인정만 판정합니다.
